## Context

Android 端通过 `AudioBridgeService` 接收 `BridgePacket.AudioFrame`，并由 `AudioPlaybackManager.write()` 将 PCM16 或 Float32 数据写入 `AudioTrack`。现有 `PlaybackStateRepository` 向 Compose 页面发布连接和播放状态，但不保留 PCM 样本。`AudioBridgeScreen` 管理主页面、详情页面和顶部操作栏，`AudioBridgeTheme` 同时提供亮色与深色配色并默认跟随系统。

本变更横跨音频写入、分析状态、Compose 绘制、页面导航和主题。分析不得阻塞网络接收或 `AudioTrack` 写入，不得让 UI 持有持续增长的 PCM 缓冲区，也不得修改 Windows 到 Android 的协议。

## Goals / Non-Goals

**Goals:**

- 在 Android 顶部操作栏中央提供主页与可视化页签切换。
- 显示左右声道频谱、L/R Lissajous 音频图像和实时短时 RMS `dBFS` 电平。
- 支持现有 PCM16、Float32、单声道和双声道会话，双声道保持左右声道独立。
- 以固定容量、最新值优先的数据流把分析结果发布给 Compose。
- 保证分析开销不阻塞音频写入，并在停止、断线或音频超时后进入明确的空闲状态。
- 强制 Android 应用使用统一深色主题，并同步系统状态栏和导航栏图标明暗模式。

**Non-Goals:**

- 不实现专业计量用途的 LUFS、峰值保持、频谱历史瀑布图或录音导出。
- 不向 Windows 端回传分析结果，不修改 TCP 包格式或发送端采集设置。
- 不为可视化加入用户可配置的 FFT 大小、刷新率、颜色主题或持久化选项。
- 不替换现有音量控制、连接管理和详情页面行为。

## Decisions

### 1. 在音频写入入口旁路发布 PCM 分析快照

`AudioPlaybackManager` 在确认帧有效后，将会话格式和当前帧交给独立的 `AudioVisualizationAnalyzer`。分析器只复制完成一个分析窗口所需的归一化样本，并以覆盖旧值的方式发布不可变 `AudioVisualizationFrame`。音频写入不等待 UI 消费，也不积压待分析帧。

分析结果通过 `PlaybackStateRepository` 的独立 `StateFlow` 发布，不并入频繁复制的业务 `PlaybackUiState`。ViewModel 将该流单独暴露给 `AudioBridgeScreen`。选择独立流而不是把原始 PCM 放入 UI 状态，可限制复制量和重组范围；选择 Android 端分析而不是 Windows 端预计算，可避免协议变更并保证显示内容与实际播放输入一致。

### 2. 使用固定窗口和限频更新

分析器把 PCM16 和 Float32 样本归一化到 `[-1, 1]`。双声道按交错顺序拆分，单声道样本复制到左右分析通道。每个声道使用固定的 4096 样本 Hann 窗执行 FFT，再聚合为固定数量的对数频带；相位图保留同一窗口内均匀抽样的 L/R 点。

分析结果最多每 33 ms 发布一次，约 30 FPS；来不及处理时丢弃旧快照并保留最新值。FFT 使用项目内纯 Kotlin 实现，避免为单一固定规模引入运行时依赖。若基准测试不能满足目标，再以固定版本依赖替换，且保持分析器接口不变。

选择 4096 样本窗口是为了提高低频分辨率；48 kHz 采样率下约为 `11.72 Hz/bin`，窗口时长约 85 ms。该变更接受更高分析延迟，并继续通过固定频带数、33 ms 发布限频和最新值覆盖控制移动设备开销。选择对数频带是为了在有限宽度内保留低频可读性，而不是逐 FFT bin 绘制。

### 3. 明确定义显示指标

左右频谱分别计算并归一化，使用不同强调色绘制，静音时平滑衰减到基线。频谱使用对数频率横轴、`dBFS` 纵轴和网格。音频图像采用 Lissajous 相位图：归一化左声道为 X，右声道为 Y，绘制中心轴和样本轨迹。短时电平分别计算左右声道同一窗口的 RMS，并转换为 `dBFS = 20 * log10(rms)`；显示范围钳制为 `-60..0 dBFS`，无有效信号显示 `-∞ dBFS`。每个声道使用浅色峰值线显示短时最大电平，保持约 700 ms 后以固定速率回落。

本指标明确标为 dBFS，不标为 LUFS，因为本变更不实现 ITU-R BS.1770 的 K 加权、门限和积分窗口。

### 4. 在顶栏中央使用分段页签导航

`AudioBridgePage` 增加 `Visualizer`。主页面和可视化页面共用一个居中的双选项分段控件，选项为“控制”和“频谱”；品牌标题保留在左侧，连接状态、重连和详情操作保留在右侧。详情页继续显示关闭操作，关闭后返回进入详情前的主功能页。

可视化页面使用稳定的两区布局：上区中央为 Lissajous 音频图像，上区右侧为 `dBFS` 电平；下区为占主要高度的左右双声道频谱。手机窄屏允许电平显示覆盖在音频图像右上角的固定区域，平板横屏使用独立右侧电平区域。所有绘图区域使用固定约束，数值变化不得引发布局跳动。

### 5. 用 Compose Canvas 绘制动态内容

频谱和相位图使用 Compose `Canvas`，只消费已计算的归一化数组。Canvas 不执行 PCM 解码、FFT 或 RMS 聚合。更新间使用短时插值或指数平滑，减少帧间抖动；关闭页面后仍可接收最新快照，但不启动绘制动画循环。

选择 Canvas 而不是大量 Composable 柱条，可避免每个频带形成独立组合节点。选择应用内绘制而不是 OpenGL，可降低实现复杂度，当前二维点线图不需要独立渲染管线。

### 6. 无数据状态由时间戳驱动

分析帧携带单调时钟时间戳。连接但尚未收到有效 PCM 时显示“等待音频”；最后一帧超过 500 ms 后，频谱和轨迹平滑归零并显示空闲状态；服务停止或连接断开时立即清除分析状态。旧会话的残留帧不得出现在新会话中。

### 7. 应用固定使用深色主题

`AudioBridgeTheme` 的应用入口固定选择 `DarkColorScheme`，不再依据系统浅色模式切换。状态栏和导航栏使用与主题背景一致的深色，并设置浅色系统栏图标。现有控制页、详情页、对话状态和可视化页只使用主题语义色，确保文字、图标、边框、滑块和状态颜色在深色背景中可辨认。

选择固定深色模式是为了让高频动态可视化保持稳定对比度，并符合本功能的视觉目标；本变更不增加主题选择设置。

## Risks / Trade-offs

- [FFT 与绘制增加 CPU 和耗电] → 固定窗口和频带数、30 FPS 限频、最新值覆盖，并用单元测试和真机性能检查确认音频线程无明显回退。
- [在音频写入路径复制样本可能增加抖动] → 只复制固定窗口、复用分析器内部缓冲区，并把 FFT 和聚合放到单独协程调度器。
- [Float32 输入可能包含 NaN 或越界值] → 解码时把非有限值归零，并将有效值钳制到 `[-1, 1]`。
- [固定深色模式改变现有浅色用户体验] → 全量检查主页、详情页、系统栏和关键状态的对比度；回滚时可恢复主题入口的系统模式参数。
- [顶栏中央控件在窄屏可能与操作按钮冲突] → 使用有界宽度的紧凑分段控件，隐藏文字品牌标题的次要空间而不移除操作按钮，并用手机宽度 Compose 测试验证无重叠。
- [RMS dBFS 与专业响度读数不同] → UI 和规格将其称为短时电平并标注 `dBFS`，不使用 LUFS 名称。

## Migration Plan

1. 增加纯 Kotlin PCM 解码和分析模型及单元测试，不接入播放链路。
2. 在播放管理器和状态仓库接入有界分析流，验证现有音频播放测试继续通过。
3. 增加可视化页面和顶栏页签，完成手机与平板布局验证。
4. 固定深色主题并检查现有页面和系统栏。
5. 运行 Android 单元测试、debug 构建和关键 Compose UI 测试，再进行真机音频连续播放检查。

回滚时移除可视化入口和分析旁路，并恢复主题入口跟随系统；协议和持久化格式未变化，无数据迁移。

## Open Questions

- 实现阶段需用目标 Android 设备测量 30 FPS 分析与绘制的 CPU 占用；若连续播放出现抖动，先降至 20 FPS，而不是扩大缓冲或阻塞写入。
